Entregável 2 — Execução nas DuckDuckGo Privacy Test Pages

Ambiente: Firefox 156.0.1 (macOS), perfil limpo criado pelo harness tools/capture_ddg.py, com as proteções nativas do Firefox desligadas (Enhanced Tracking Protection, partição de cookies/estado de rede, query stripping, bounce tracking protection, resistFingerprinting) para que o plugin observe o tráfego sem interferência do navegador. Para cada página: o resultado esperado é o que a própria página reporta (texto na tela e, quando existe, o JSON gerado pelo botão "Download the result", salvo em evidencias/ddg/NN-*-resultado-pagina.json). O resultado do plugin vem do JSON exportado pelo plugin (evidencias/ddg/NN-*.json). O print evidencias/ddg/NN-*.png mostra a página de teste (esquerda) e o relatório do plugin para aquela aba (direita).

Síntese

  • Cobertura: o plugin reproduziu os resultados da página em todos os testes de rastreadores (1–5), storage (6), fingerprinting (8–9), bounce (10) e query parameters (11), e produziu o comportamento correto em 12.
  • Divergências estruturais (não são erros de detecção): o plugin é um observador, não um bloqueador por padrão — não aplica surrogates (4), não remove query parameters (11) e não particiona storage (7). O bloqueio existe apenas pela lista personalizada (5b).
  • Limite de arquitetura: relatório por aba. Testes que abrem janelas secundárias (7) espalham a evidência em dois relatórios; o plugin registra a janela aberta para permitir a correlação.
  • Limite de instrumentação: WebSocket só é visto pelo hook do construtor quando o handshake não passa pelo webRequest (5a); canais de persistência indiretos (window.name, history, cache HTTP) não são instrumentados (6).

  5. Momento. Os scripts de terceiros mudam ao longo dos dias; os dois relatórios devem ser produzidos na mesma data sempre que possível.

O plugin é mais sensível e menos específico; por isso o peso (10) só se aplica quando o script é um rastreador conhecido no frame principal — o que ainda assim pune a Marfeel por um listener de engajamento. É a dedução mais discutível da nota do UOL; sem ela, e sem o "hijacking alto" que ela dispara (15), o UOL teria 25 (E) — o conceito não muda.

O Blacklight conta mercadoclics.com, mercadolibre.com e meli.com como terceiros (3 cookies); o plugin os trata como mesma organização e o ML fica com 0 cookies de 3ª parte. Se a convenção do Blacklight fosse adotada, o ML perderia 6 pontos (3 cookies) e mais 4 (mercadoclics como rastreador), caindo para 69 (C). A escolha do plugin é deliberada: a nota mede rastreamento entre organizações; o rastreamento dentro do grupo continua visível na interface (rótulo "afiliado"), mas não pontua.
  5. O que o Blacklight não mede. Cookie sync explícito, polling, storage em iframes e alterações no ambiente JS (hijacking) entram só na nota do plugin. No UOL respondem por 27 dos 101 pontos deduzidos.

Limites da metodologia. (a) A nota depende do que a visita disparou — sem leilão de anúncios, sites de mídia parecem menos invasivos do que são para um visitante estrangeiro. (b) A lista interna de rastreadores é curada e menor que a do DuckDuckGo/EasyPrivacy usada pelo Blacklight e pelo uBlock; domínios "não listados" pontuam pouco (1 ponto). (c) Os tetos evitam que um único eixo domine, mas fazem a escala saturar: o UOL chega a 0 com folga, e não é possível distinguir "muito invasivo" de "extremamente invasivo" abaixo desse ponto.
